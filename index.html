本地工具指南

项目初始配置为 HTTP 服务器来源。执行 Local 切换命令后才读取本地；执行服务器配置命令后恢复 HTTP 并保存填写的地址。配置会持续生效，不由网页下拉选择直接改写。

1. 准备文件并打开 PowerShell

保留完整项目目录，确认有 keyrun.ps1、switch-source.ps1、resource-loader.ps1、source-config.json、scripts/、ja-netfilter/ 和 licenses/。打开 PowerShell，进入本地项目：

Set-Location '你的项目地址'

将「你的项目地址」替换为本机项目文件夹路径，再执行后续相对路径命令。快速命令区会在本地页面中自动填写实际路径。此步骤用于 Local 本地入口。

2. 切换为 Local：直接读取磁盘

首次本地运行建议使用 Local。在快速命令区选择 Local，复制并执行切换命令：

powershell.exe -NoProfile -File .\switch-source.ps1 -Mode local

切换成功后，source-config.json 的 mode 为 local。默认根目录是项目所在目录，不依赖 PowerShell 当前工作目录，也不需要启动 HTTP 服务。

3. HTTP：部署项目与使用服务器入口

项目维护者：在完整项目目录中执行下面的服务器配置命令，填写实际部署根地址。它会保存 HTTP 来源并更新 Windows 引导脚本内的地址与代码校验信息。完成后将完整项目发布到该 HTTP/HTTPS 根目录：

powershell.exe -NoProfile -File .\switch-source.ps1 -Mode http -HttpBase 'https://liyangxu1.github.io/keyrun'

最终使用者：服务器提供完整文件后，打开 PowerShell，确认脚本来源，直接使用服务器命令，无需先下载本地项目或执行本地配置切换：

irm https://liyangxu1.github.io/keyrun/ps1 | iex

Windows 引导会获取并校验所需代码，准备临时工作目录，再从服务器读取安装资源。脚本仍在你的电脑上执行，完成后清理临时文件。修改项目代码后，部署者应重新执行服务器配置命令再发布，避免版本校验不一致。

默认旧地址在 2026-10-14 核对时返回 404，只作示例。请换成你实际部署的可信服务地址。服务器配置命令供部署者使用；使用已部署服务不需要本地项目。

4. Local 本地处理命令

  1. 先备份 IDE 配置和已有许可证文件，关闭所有 JetBrains 软件。
  2. 执行下面的处理命令，按脚本提示继续，并允许管理员权限请求：
powershell.exe -NoProfile -File .\keyrun.ps1 -Install

这是 Local 的本地入口，在第 2 步切换 Local 后运行。脚本会先检查资源，再执行环境变量清理、工作目录部署、Java Agent 启动参数及 key 文件处理。完成后重新打开 IDE 检查结果。

5. 仅查看路径，或处理运行问题

只读诊断会逐个显示发现的所有配置文件，不运行安装，也无需关闭 IDE：

powershell.exe -NoProfile -File .\keyrun.ps1 -DiagnoseIdeaPaths
  • 仍在请求服务器：必须执行 Local 切换命令才能改变默认服务器来源。页面选择不保存配置；之前保存的模式会持续生效。
  • 引导校验失败：部署者重新生成 ps1 并发布匹配版本的代码文件，不能只上传部分更新。
  • Local 文件缺失：检查项目资源是否完整，以及配置的 localRoot 是否正确。
  • HTTP 404、超时或连接失败：检查根地址、对应资源路径和服务器状态；重定向地址需要换成最终地址。
  • 找不到产品或文件被占用：查看日志中的安装目录和 .home 提示，确认产品已正确安装并关闭 IDE。
  • 执行策略或管理员权限限制：按系统或组织的脚本运行要求处理。移动项目后重新打开本地网页，再复制命令。

将完整项目放入本地目录，打开「终端」。将「你的项目地址」替换为项目文件夹的实际 POSIX 路径：
